# Webtoon Reader — Задачи

> Третий документ методологии OpenSpec. Рабочий план реализации. Источники истины: `docs/proposal.md` (цели, стек) и `docs/design.md` (дизайн-система). Каждая задача содержит файлы, критерии готовности (DoD) и зависимости.

## Как читать документ
- **ID задачи** — `X.Y`, где `X` — номер этапа
- **DoD** (Definition of Done) — объективные проверки готовности; задача закрыта только когда выполнены все пункты
- **Зависит от** — задачи, обязательные к выполнению раньше
- Порядок внутри этапа — сверху вниз. Этап не начинается, пока не закрыт предыдущий, если в описании не указано «[параллельно]»

## Этап 0 — Подготовка окружения

- В `vite.config.js` добавить `@vitejs/plugin-react`; сохранить `base: './'`
- **Зависит от:** —
- **DoD:**
  - `npm install` проходит без ошибок, пакеты видны в `package.json`
  - `npm run dev` поднимает дев-сервер
  - `npm run build` собирает `dist/` без ошибок и предупреждений

### 0.2 Точка входа и структура папок
- **Файлы:** `index.html`, `src/main.jsx`, `src/index.css`, `src/App.jsx`
- **Папки:** `src/components/`, `src/routes/`, `src/styles/`, `src/animations/`, `src/data/`, `src/lib/`, `src/hooks/`, `public/fonts/`, `public/images/`, `scripts/`
- В `index.html`: `<div id="root">`, viewport, `lang="ru"`, подключение `src/index.css` и `src/main.jsx`
- **Зависит от:** 0.1
- **DoD:**
  - В браузере рендерится заглушка приложения, HMR перезагружает без полного обновления
  - `index.html` валиден, нет консольных ошибок

### 0.3 Маршрутизация и страницы-каркасы
- **Файлы:** `src/App.jsx`, `src/routes/HomePage.jsx`, `src/routes/ReaderPage.jsx`, `src/routes/NotFoundPage.jsx`
- **Маршруты:** `/` → HomePage; `/read/:chapterId/:pageNum` → ReaderPage; `*` → NotFoundPage
- **Зависит от:** 0.2
- **DoD:**
  - Прямой вход по URL `/read/1/1` рендерит страницу читалки (заглушка), без 404
  - Навигация «роутером» не перезагружает страницу
  - Неизвестный путь отдаёт NotFoundPage

### 0.4 Исходный контент → public
- **Файлы:** `public/images/art/**` (из `sources/ART/`), `public/pages/chapter-{1,2,3}/**`, `public/images/hero-poster.webp`
- **Зависит от:** —
- **DoD:**
  - Все арты из `sources/ART/` доступны по `/images/art/...` (проверка в браузере — статус 200)
  - Минимум 3 главы комикса; глава 1 — не менее 10 страниц, главы 2–3 — не менее 5
  - Постер hero в формате WebP доступен по `/images/hero-poster.webp`

### 0.5 Привязать репозиторий GitHub
- **Файлы:** `.gitignore`, `README.md` (краткое описание + ссылки на `docs/`)
- Инициализация git: ветка `main`, первый коммит, remote `origin`, `git push -u origin main`
- `.gitignore` исключает: `node_modules/`, `dist/`, `.env*`, IDE-папки, системные файлы (DS_Store, Thumbs.db)
- **Зависит от:** — (выполняется в начале этапа; блокирует 0.6)
- **DoD:**
  - `git log` показывает первый коммит в `main`, `git push -u origin main` проходит успешно
  - Клонирование репозитория в чистую папку воспроизводит проект (`npm install` + `npm run dev`)
  - В репозитории отсутствуют `node_modules/`, `dist/` и любые env/secrets-файлы

### 0.6 Правила деплоя (GitHub Actions + GitHub Pages)
- **Файлы:** `.github/workflows/deploy.yml`, настройки репозитория (Settings → Pages, защита ветки)
- Workflow: на push в `main` → `npm ci` → `npm run build` → публикация `dist/` на GitHub Pages (источник: GitHub Actions)
- Ветки: `main` — прод; `feat/*` — фичи; `fix/*` — багфиксы. Merge в `main` только через PR с закрытым чек-листом DoD
- Защита ветки `main`: запрет прямых push, обязательный PR (настройка через `gh` или веб-интерфейс)
- Дополнительное правило: `dist/` не хранится в git (собирается в CI); контент-ассеты в `public/`
- **Зависит от:** 0.2 (нужен рабочий билд для валидации), 0.5
- **DoD:**
  - Push в `main` автоматически запускает workflow, он проходит зелёным
  - Сайт доступен по `https://<owner>.github.io/<repo>/` и передеплоивается при каждом мердже
  - Сборка идёт с `base: './'` — сайт работает из подпапки (проверка в задачах 7.3)
  - Прямой push в `main` невозможен, изменения попадают только через PR
